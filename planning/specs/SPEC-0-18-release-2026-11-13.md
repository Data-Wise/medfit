## Assumptions

1. 0.18.0 is a minor, additive, GitHub-only release from `dev` to `main` (CRAN deferred, #83). No existing fit's numbers
   change; no argument, export or class property is removed.
2. The plan file owns task state; this spec owns the acceptance contract. When they disagree, the ADR decides, and both
   files are corrected in the same commit.
3. S1 is implemented on `feature/engine-sem` (commits `60553cf8`, `c5338cb1`; QA PASS; final gates running at the time of
   writing). This spec applies to it unchanged.
4. S3 is deferred to docs only (V-3), S6 is unscheduled (waits for the D-4 gate), and S5b ships only if its build
   confirms the redirect template. The spike that tested it passed on 2026-11-13.
5. The private `medfit-book` repository is not edited; its `engine = "native"` calls keep working through the alias.

## 1. Objective

Rename the in-package maximum-likelihood fitter from "native" to **the sem engine** without breaking a single existing
call. Give its tuning one documented entry point (`sem_control()`), and make two-level provenance ready for a fitter
other than lavaan. Users: analysts calling `fit_mediation()`, `fit_sem()` and `mbco_sem()`, and the dependents (probmed,
RMediation, missingmed). Success means three things:

- A reader of the site meets one vocabulary: engine, then estimator, then optimizer.
- Every 0.17.0 script runs and gives `identical()` numbers.
- The release notes list only additions.

## 6. Code style

Match the surrounding R: native pipe, `checkmate` at every entry, snake_case functions, CamelCase classes,
`.`-prefixed internals, explicit namespacing, lines of 120 columns or fewer, and US English. Normalize a public
spelling once, at the boundary; do not compare two strings downstream. The S1 shape is the pattern:

```r
.fit_mediation_engines <- c("glm", "regmedint", "lmer", "sem", "native")

checkmate::assert_choice(engine, .fit_mediation_engines, .var.name = "engine")
if (identical(engine, "sem")) engine <- "native"   # one internal value; "native" is the legacy spelling
```

S7 methods get `@noRd`; a new export gets roxygen with `\eqn{latex}{ascii}` math and an entry in `_pkgdown.yml`.

## 7. Testing strategy

- **Test-first, with a planted defect per behavior.** Each requirement row names the defect its test must catch. QA
  re-runs it and records caught/missed.
- **Numeric neutrality is the core oracle.** Every module compares the branch to an `origin/dev` build:
  - Use `identical()`, with `ignore.environment = TRUE` where `gaussian()` closures differ.
  - Use the existing tolerance where a test already pins one.
  - For native fits, add lavaan as the independent check: coef to about 1e-15, SEs to about 1e-12.
- **S2 has extra gates.** It needs the seven-item checklist and a reliability cell. Its metamorphic invariance test is
  that `auto`, `slsqp` and the legacy list give `identical()` fits. It also needs a fault injection (a conflicting
  `algorithm`) and a platform run on the OpenBLAS runner via `gh workflow run gates.yaml --ref <branch>`.
- **S4 compatibility.** A committed 0.17.0 `.rds` fixture, regenerated only by its script.
- **Levels.** Unit tests are per module. The full suite runs once per module, in that module's worktree. The
  docs-consistency tests run in the docs stage. The release-level checks are listed in R-20.

## 8. Boundaries

- **Always:**
  - Work test-first in a feature worktree off `origin/dev`.
  - Quote exact commands and counts.
  - Keep numbers identical, and say so in the PR body.
  - Run the risk tier with the real PR body.
  - Use US English.
  - Keep `_agents_workspace/` uncommitted.
- **Ask first:**
  - Pushing, opening a PR, merging, tagging, or any release step.
  - Changing an ADR decision.
  - Adding a dependency.
  - Editing CI workflows.
  - Starting S5b's renames.
  - Running S2 beside another `fit-sem.R`/`sem-optim.R` change.
- **Never:**
  - Change a numerical result or the solver path.
  - Warn on `engine = "native"` in 0.18.0.
  - Rename `compare_lr(engine = )`.
  - Remove `lavaan_version`, `source` or any pinned argument.
  - Write code on `dev` or `main`.
  - Edit `medfit-book` or another repository.
  - Bulk `replace_all` "native".

## 9. Success criteria

- R-1 to R-21 are met, with each module's PR merged to `dev` and green on its fast checks.
- The S2 checklist is complete and both `gates` shards are green on the OpenBLAS runner.
- The release evidence (R-20) is attached to the release PR.
- `test-api-freeze.R` passes with every 0.17.0 formal unchanged.
- A 0.17.0 script that uses `engine = "native"`, `control = list(...)` and a saved `TwoLevelMediationData` runs on the
  0.18.0 tag. Its numbers are `identical()` to 0.17.0's, and it prints no new warning.
