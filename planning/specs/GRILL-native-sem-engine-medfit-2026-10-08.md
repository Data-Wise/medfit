## P0 facts (scratchpad run, 2026-10-08; no medfit writes)

- OpenMx SEs are observed-information: latent model (n = 300) max SE diff vs OpenMx is 5.0e-6 for observed info at scale n/2, 2.4e-3 for expected. Saturated path model: observed = expected, 3.4e-7. (n-1)/2 scale is worse (2.1e-4, 9.5e-5). **One model, one seed, so the observed-information default (J9) is provisional until the N5 SE gate (K10) passes.**
- Covariance convention: OpenMx treats `type = "cov"` input as unbiased and rescales internally. Input `S * n/(n-1)` reproduces divisor-n estimates (max diff 2.3e-6 latent, 2.2e-7 observed); the divisor-n matrix shrinks variances by exactly (n-1)/n (0.9975 at n = 400).
- Sweep: `fit_mediation()` accepts `engine` in `c("glm", "regmedint")` (`R/fit-glm.R:170`); base `stats::deriv()` differentiates `+ - * / ^ exp log sqrt` and errors by name on anything else.

| K10 | Is "observed information by default" (J9) established? The gate below makes it a defined, reproducible test. |

**N5 SE gate (defines what "passes" means):**

| Dimension | Levels |
|---|---|
| Model structures (at least 5) | observed path model with covariates; latent mediator; parallel two-mediator; serial two-mediator; one constrained model (`a == b` or `a + b == c`) |
| Sample sizes | 50, 200, 1000 |
| Seeds | at least 20 per cell, fixed in the script |
| Oracle | OpenMx with input `S * n/(n - 1)` (P0 convention); both engines at the same optimum, so the comparison is of SEs at the solution |
| Pass criterion | max relative SE difference below 1e-3 for observed information in **every** cell that has a proper solution; the expected-information difference is recorded alongside for contrast |
| Improper-solution cells | cells with a negative variance or an active bound are **reported separately with their counts, not dropped**; the gate states the pass rate over proper cells and lists the improper ones |
| Reproducibility | the script (grown from `p0.R`/`p0b.R`, plan task T5) lives in `planning/specs/evidence/` with package versions and seeds |

The 1e-3 relative tolerance is a proposal, not yet calibrated: P0 measured an absolute SE difference of 5.0e-6, but the SE magnitudes were not recorded, so the relative figure is unknown. OpenMx's Hessian is numeric, so a very tight bound would test its differencing and not our information matrix. Calibrate the tolerance on the first gate run, record the observed maximum, and then freeze it.

## Research: speed and package choice (2026-10-08; scripts, outputs and package versions in `evidence/native-sem-2026-10-08/`, README there)

| Finding | Evidence |
|---|---|
| **The cost is R interpreter overhead, not the math (latent fixture: 6 variables, 10 parameters; `05`).** The spike's `mats()` loops over the parameter table in R. Precomputed index vectors, `chol` for the log-determinant and trace, and `crossprod` give identical values (max diff 1.8e-15 f, 1.3e-15 gradient) at 31 us per f+g versus 710 us (23x). | `nlminb` fit: 12.4 ms to 1.1 ms (11x). |
| **Speed: optimizer choice stops mattering once the objective is fast (latent fixture, `05b`).** | nlminb 1.1 ms, nloptr LBFGS 1.6 ms, nloptr SLSQP 2.6 ms per fit (estimates within 1.2e-8 of nlminb); with the spike objective 13 / 17 / 28 ms. Across all three model shapes and n of 50, 200, 1000 (`03`, default starts) the SLSQP/nlminb gap stays about 2x (23-29 ms vs 12-13 ms with the slow objective). SLSQP's cost is negligible, and it is the only one of these with constraints. |
| **Reliability, broader grid (`03`: 3 model shapes x n of 50, 200, 1000 x 30 datasets per cell, 90 cells; match = implied covariance within 1e-5 of lavaan).** Default (moment-based) starts: all five solvers (nloptr SLSQP, nloptr LBFGS, nlminb, `optim` BFGS, ucminf) matched in **every** cell. Random starts (default start perturbed by U(-0.5, 0.5)): nlminb 100%, SLSQP 98.5%, ucminf 98.2%, `optim` BFGS 97.0%, **nloptr LBFGS 93.3%** (mean over cells; worst cell 86.7%, obs_cov at n = 200). So "optimizer choice stops mattering" holds for **speed and default starts only**; it does not hold for poor starts. | Implication for J6 (not re-litigated, flagged for the author): L-BFGS, J6's choice for unconstrained fits, was the least reliable from random starts; SLSQP everywhere would cost 2x time but gain 5 points of reliability, and nlminb (excluded by J6) was best. A failed start is not a wrong answer when the multi-start retry (N3) and the convergence flag catch it, but the engine should not rely on one start. Caveats: 30 datasets per cell (one failure = 3.3 points); a mismatch may be the solver stalling or lavaan sitting on another local solution (not separated); alabama `auglag()` refuses unconstrained problems. |
| **Constrained, 10 starts each (observed three-variable fixture, n = 300; `04`, `04b`).** Linear `a + b == 0.5`: nloptr SLSQP 10/10 and alabama 10/10 at the best objective (11 ms vs 31 ms per solve). Nonlinear `a*b == 0`: both feasible 10/10 but start-dependent; SLSQP reached the better solution from 6/10 starts (one start at (0, 0) stalled at F = 1.03), alabama from 9/10 (about 4x slower). | Confirms the design of solving `a == 0` and `b == 0` separately (N7) instead of one nonlinear solve. Solutions: F = 0.0952 (`a` = 0) and 0.1061 (`b` = 0), i.e. lavaan's fmin/2 values. |
| **Sparse matrices do not help at mediation sizes (synthetic lower-triangular `A`, not fitted models; `05`).** `(I - A)^-1` with about 3 nonzeros per row: dense wins up to p = 30 (30 us vs 200 us); crossover near p = 100; sparse wins from p = 300 (400 us vs 1.4 ms) and p = 1000 (1.6 ms vs 18 ms). | Mediation models have p of about 5-30. Not worth the `Matrix` dependency in v0; revisit only for large-p latent models. |
| **Parallelism helps across fits, not within one (200 latent-model fits; `05`).** 200 fits: 0.22 s on 1 core, 0.15 / 0.09 / 0.07 s on 2 / 4 / 8 (18 cores available). | Gains only matter for MI, bootstrap and multi-start at large counts; the matrices inside one fit are too small to thread. `parallel::mclapply` is already what the bootstrap uses (Unix only). |
| **Not tested here:** Rsolnp and lbfgsb3c failed to link on this machine (Homebrew gcc library path missing `emutls_w`), a local toolchain fault, not a package verdict. optimx, ROI, RTMB/TMB, torch and RcppArmadillo were not benchmarked. | A hand-written C++ objective would cut the remaining 31 us further, at the price of compiled own-code in a package that already takes a compiled dependency (J3). |
