## Numerical results

On both R 4.6.1 and 4.6.2, medfit's parity, constrained, SE and nonlinear-parity gates passed all 29 checks; nonlinear-profile and semopy also passed, with 144/144 and 350/350 rows respectively. The seven paired CSVs, including stationarity rows, matched exactly in row order, statuses and all reported numeric fields (`cross-version.txt`). Initial parallel-gate attempts failed because the sandbox hid available CPU cores; retries with core detection available passed. R 4.1 and 4.5 passed all 41 checks across the five OpenMx gates, and each passed all 7 semopy checks (350/350 rows). These gate outcomes apply to the selected fixtures, not arbitrary models.

The independent MPFR erfc reference used 256 and 512 bits, analytic symmetry, both tails and log probabilities, the plan's z grid plus significance-boundary values. No tested 0.05 or 0.001 decision crossing occurred. R 4.5 and both 4.6 versions met the plan's screening thresholds; on R 4.1 ordinary `pnorm(38, lower.tail=FALSE)` returned zero while the reference is approximately `2.885428351e-316`. Log-tail output remained usable. The actual probmed parallel closed-form function similarly returned zero at a constructed standardized value of -38 only on R 4.1. This is an extreme representable subnormal, not evidence of a decision change at the tested thresholds.

A controlled RMediation product-integrand probe finds cancellation from `1 - pnorm(z)` in both scalar and vector paths (`R/prod3_core.R`): at z=20 the integrand is zero even though the density-scaled independent survival probability is about `1.61e-90`; at z=8 it has roughly 7% relative error. This is shared across the tested R versions; no resulting material error in an integrated probability has been established. Medrobust's inspected Imbens–Manski examples with standardized bound widths 0, 5, 20 and 38 matched across these versions. Source probes and raw MPFR data are `ecosystem-tail.R`, `ecosystem-tail-*.log`, `tail-oracle.R`, and `tail-*.csv`.

## Investigation update: interrupted checks

The selected medfit source archive fails the same two tests on all four R versions, including 4.6.1 and 4.6.2. The D4 failure is an archive packaging defect: `.Rbuildignore:32` excludes `tests/sim`, but `tests/testthat/test-sem-d4-covariance.R:262` parses `tests/sim/sem-nonlinear-gate.R`. Local tests with the source tree present can therefore pass while `R CMD check` of the built archive fails.

The other failure is an integration contract mismatch. In `test-sem-probmed.R:125`, a latent mediator named `eta` is absent from the observed data. In the selected probmed source, `.pmed_compute()` calls `.check_supported_extract()` before dispatching to the chosen method; `.check_supported_data()` checks `data[[eta]]` as numeric even when that column is absent. The plug-in path reads estimated paths and residual parameters, but whether the correct repair is to change validation, extraction, or the example requires a separate contract review and tests. The observed failure occurs on all four versions and is not evidence of a 4.6.2 regression.

For R 4.1, an isolated RMediation experiment reproduced the failure in `.resolve_path_indices()` with the same `MediationData` object: its ordinary namespace reports `trying to get slot "vcov" ... that is not an S4 object`; cloning the function with S7's exported `@` operator in its environment returns indices `1,2`. The selected RMediation namespace imports S7 helpers but not `@`. This directly establishes the operator-binding cause for that resolver; importing S7's operator is a candidate repair, not a verified whole-package fix. medrobust and missingmed also show S7 property errors on 4.1, but their individual causes, replacement operators and remaining test failures still need validation. RMediation's separate `stats4`/`setGeneric` namespace-load error is not explained by this experiment.

## Local compatibility fixes and follow-up — 2026-10-29

The revised candidate includes only the nonlinear gate and skips the product-only pinning test when its full scripts are absent, as archive checks already skipped the full product harness. The complete source tree retains its original product tests. The revised archive was built for verification.

A separate local probmed checkout at `.worktrees/probmed-r-compat-fix` on branch `codex/r-compat-latent` at local commit `da431e3` changes the guard to allow an absent mediator column only for the Gaussian plug-in. Treatment and observed mediator type checks remain; nonparametric bootstrap and non-Gaussian plug-in do not receive the exception. Its regression tests compare identical seeded plug-in estimates with and without the stored data, check an independent closed-form Gaussian probability, and assert that invalid observed variables and unsupported cases still fail. Focused guard tests passed on R 4.1.3 and 4.6.2. No evidence establishes general latent support for other families or bootstrap methods.

R 4.1 S7 follow-up: adding S7's exported `@` in an otherwise unchanged function environment turns medrobust's `sensitivity_region` print failure into success. Re-evaluating missingmed's `MbcoMIResult` class source in an environment containing the same operator turns its example constructor's `@ariv` failure into success. Along with the RMediation resolver probe, these isolate three individual namespace-binding failures; they do not prove every failure in the three packages has that cause.

R 4.1 `stats4` follow-up: under `R_DEFAULT_PACKAGES=NULL`, calling `loadNamespace("stats4")` directly fails with `could not find function "setGeneric"` before any ecosystem package is loaded; loading the methods namespace alone does not fix it, while starting with `R_DEFAULT_PACKAGES=methods` succeeds. The same base-only probe succeeds on R 4.5.3. The local `stats4` NAMESPACE matches the [R 4.1 branch source](https://raw.githubusercontent.com/wch/r-source/R-4-1-branch/src/library/stats4/NAMESPACE), which omits `setGeneric`; the [R 4.5 branch source](https://raw.githubusercontent.com/wch/r-source/R-4-5-branch/src/library/stats4/NAMESPACE) imports it. The reproduction and source comparison identify an independent base-package/initialization issue in this installation, not an ecosystem-package root cause. Do not hide the warning by attaching methods during a clean namespace check; verify against an independently installed official R 4.1 distribution before attributing it to R 4.1 generally.
