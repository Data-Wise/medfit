# Goals for unattended runs (2026-11-10)

How to use: paste one goal line into `/goal`. Each goal is a verifiable end state plus explicit standing authorizations, so the
Stop hook can judge "done" from evidence and the session needs no questions. Run them in order; goal 2 assumes goal 1 is
done. The task-level breakdown is `PLAN-twolevel-and-docs-finish-2026-11-10.md`. Goals never touch the items in "Out of scope".

## Standing authorizations (apply to every goal below; given by the maintainer by running the goal)

- Create feature worktrees off `dev`, commit, push feature branches, open PRs against `dev`.
- Merge a PR into `dev` with a squash merge pinned to its head (`--match-head-commit`) once all of these hold: every hosted
  check on that exact head passed; the diff leak scan (secrets, PII, literal destructive git commands) is clean; the PR is
  mergeable; it belongs to a goal below. Then verify `git merge-base --is-ancestor <merge commit> origin/dev`, remove the
  merged worktree, and report every merge in the final message.
- Merge `dev` into a feature branch to resolve conflicts (never rebase, never force-push).
- Delete a merged local branch only with `git branch -d`; when the branch guard blocks a squash-merged branch, list the one-line
  command in the final report instead of working around the guard.

## Out of scope (never do, never ask; stop and list instead)

FIML admission studies (plan section 5), the Hopper stage-0 run, medsim P0 scope, any release, tag, GitHub release, version
bump to `main`, CRAN step, merge into `main`, branch-protection or ruleset changes, force-push, native two-level fitter (S4),
latent-mediator two-level (S5), the object-based bootstrap API, anything outside `Data-Wise/medfit`.

## Stop conditions (stop and report; do not improvise)

An independent oracle disagrees with the code; a code-review finding is a correctness bug the worker cannot fix with a
test-first change; a PR check fails twice for a reason that is not a plain defect in the PR; a scope or statistical-claim
decision is needed that the specs and grill ledgers do not settle; an action would touch an out-of-scope item.
